# AGENTS.md

This document provides an overview of the project structure for developers and AI agents working on this codebase.

## Project Overview

Huddle — a marketing landing page for a youth management app built for Friday
night youth groups. Built with TanStack Start, prerendered to static HTML, and
deployed on Cloudflare Pages.

### Tech Stack

| Layer | Technology |
|-------|------------|
| Framework | TanStack Start |
| Frontend | React 19, TanStack Router v1 |
| Build | Vite 7 |
| Styling | Tailwind CSS 4 |
| Language | TypeScript 5.7 (strict mode) |
| Forms | Formspree (`@formspree/react`) |
| Deployment | Cloudflare Pages |

## Key Concepts

### Static prerendering

`vite build` renders every route to static HTML in `dist/client`. Cloudflare
Pages serves that directory directly — there is **no** server runtime, Worker,
or Pages Function. Anything needing a server would have to be added
deliberately (a `functions/` directory would turn on Pages Functions).

This is why full page content appears in `dist/client/index.html`: SEO and
social crawlers get real markup, not an empty SPA shell.

### File-Based Routing (TanStack Router)

Routes are defined by files in `src/routes/`:

- `__root.tsx` — Root layout wrapping all pages
- `index.tsx` — Route for `/`

`src/routeTree.gen.ts` is generated at build/dev time and is gitignored.

### The interest form

`EarlyAccessForm` in `src/routes/index.tsx` posts straight to Formspree from the
browser using `useForm(FORMSPREE_FORM_ID)` from `@formspree/react`. It is the
only way to contact Huddle — there is no published mailbox, so do not
reintroduce a `mailto:` link.

- The form ID is a public identifier — no secret, no env var, nothing to
  configure in Cloudflare.
- `state.submitting` / `state.succeeded` / `state.errors` drive the button, the
  success panel, and the inline error line.
- A hidden `_gotcha` honeypot field is included; Formspree discards submissions
  that fill it in.
- `_subject` is built from the ministry name, so the notification subject reads
  "Huddle — interest from <ministry>".

Submitted fields:

| Field | Name | Required | Notes |
|-------|------|----------|-------|
| Group size | `group-size` | — | Range input, 5–150 step 5 |
| Youth ministry | `ministry-name` | Yes | Also drives `_subject` and the success line |
| Location | `location` | No | Free text on purpose — suburb, state, country, or nothing |
| Email | `email` | Yes | Must stay named `email` so Formspree uses it as reply-to |

Nothing on the page promises early access — the CTA reads "Count me in" and the
section eyebrow "Register your interest". Keep it that way; the product is not
shipping yet.

Keep the existing visual design intact when changing submission plumbing: the
slider, counter, and size label ("Intimate crew" → "Movement"), the ministry
name joining that label line, the tick that springs into a filled field, the
rotating location examples, and the success state. That personality is
deliberate.

Focus and filled styling is derived from React state (`focusedField`, the
controlled values) rather than written onto the DOM in `onFocus`/`onBlur` — a
re-render while typing would otherwise wipe the focus ring.

## Development Commands

```bash
npm run dev        # Vite dev server on port 3000
npm run build      # Production build + prerender into dist/client
npm run preview    # Serve the built site via Wrangler, as Cloudflare Pages will
npm run deploy     # Build and publish to Cloudflare Pages
npm run typecheck  # tsc --noEmit
```

## Deployment

Cloudflare Pages, project `tryhuddle`, as a **direct-upload** project — the
Pages Git integration is not used. `.github/workflows/deploy.yml` builds on
push to `main` and publishes `dist/client` with `cloudflare/wrangler-action`.
`main` publishes to production; other branches get preview deployments.

The build must run before `npm run typecheck` in CI: `src/routeTree.gen.ts` is
generated by the build and is gitignored, so a fresh checkout cannot typecheck
without it.

Required repository secrets:

| Secret | Value |
|--------|-------|
| `CLOUDFLARE_API_TOKEN` | Token with the "Cloudflare Pages — Edit" permission |
| `CLOUDFLARE_ACCOUNT_ID` | The Cloudflare account ID |

`npm run deploy` still publishes straight from a workstation via wrangler's own
OAuth login, which is the quickest way to ship a fix without waiting on CI.

`public/robots.txt` and `public/sitemap.xml` hardcode the site origin — update
both when a custom domain is attached.

## Conventions

### Naming
- Components: PascalCase
- Utilities/hooks: camelCase
- Routes: kebab-case files

### Styling
- Tailwind CSS utility classes, with inline `style` objects for one-off values
  (brand purple `#7C3AED`, shadows, transforms)
- Scroll-reveal animation classes (`.reveal`, `.reveal-scale`, `.reveal-left`,
  `.reveal-right`, `.divider-animated`, `.story-line`) are wired up by the
  `useReveal` IntersectionObserver hook in `index.tsx`

### TypeScript
- Strict mode, `noUnusedLocals` and `noUnusedParameters` are on
- Import paths use the `@/` alias
- Type-only imports use the `type` keyword

### State Management
- React hooks for local state; no global store in use
